## 2. Portfolio-wide unknowns

The source register does not establish:
- Founder-approved priority or ranking
- Project-specific human owner beyond the Founder / CEO's overall accountability
- Active Virtual AI assignments
- Approved start dates, deadlines or release dates
- Approved budgets, revenue, costs or profitability
- Completion percentages or verified delivery stages
- Validated customer commitments or contractual obligations
- Confirmed milestone dates or capacity

These fields must remain Not yet assessed / Not confirmed until evidence or an explicit CEO decision is recorded.

## 3. Next discovery actions

For each initiative, create a separate discovery record:
1. Confirm official project identity and repository / document locations.
2. Inspect current authorized source artifacts and version history.
3. List requirements and distinguish confirmed from previously discussed.
4. Identify scope gaps, dependencies and technical constraints.
5. Record build / test evidence only when actually run and observed.
6. Identify security, privacy, regulatory and operational risks.
7. Prepare a scope proposal and decision questions for CEO review.

- Keep historical values and decision references.
- A proposal is not an approved decision.
- A repository README or old chat alone does not prove current delivery status.
- A successful local build does not prove production release.
- A project role suggestion is not an active assignment.

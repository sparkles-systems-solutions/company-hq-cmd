# Proposed Project-to-Role Assignment Matrix

**Status:** Proposal for Founder / CEO review  
**Source:** Current company project register and CMD Role Permission & Data Access Matrix  
**Important:** These are suggested supporting roles, not confirmed project owners or active assignments. The Founder / CEO remains the only confirmed human accountable owner. Project scope, priority, deadlines, budgets and current delivery states must be verified separately.

## 1. Common governance roles

The following roles may support most projects when explicitly assigned:

- **GM:** consolidated company-level progress reporting and escalation.
- **COO:** operating coordination and process review.
- **Head of PMO / Project Manager:** project plan, milestones, dependencies and risks.
- **Business Analyst:** requirements, process mapping and acceptance criteria.
- **Project Coordinator:** action tracking and meeting records.
- **CTO:** technical direction and architecture oversight for software/technology work.
- **Solution Architect:** solution design and integration boundaries.
- **Lead Developer:** engineering review and standards where software is developed.
- **Head of QA / QA Manager:** independent test strategy and quality evidence.
- **Release Manager:** release readiness documentation; not release approval.
- **Security lead / Security & Privacy Analyst:** security and privacy review when relevant.
- **Technical Writer / Documentation Officer:** controlled technical and user documentation.
- **Knowledge Base Coordinator:** knowledge organization and review.

These roles are not automatically assigned to every project. Each assignment needs a project-specific scope and approval.

## 3. Project assignment lifecycle

1. Verify the project exists and inspect its current repository and documents.
2. Confirm scope, deliverables, dependencies and exclusions.
3. Propose one accountable project workflow lead and supporting roles.
4. Define each role's exact task, allowed modules, data scope and output.
5. Define independent QA / security review.
6. Submit assignment proposal to Founder / CEO.
7. Record explicit approval before activation or access changes.
8. Assess deliverables and retain evidence.
9. Keep production release, financial and external actions behind separate CEO approval gates.

## 4. Fields intentionally not assigned

The current evidence does not establish project-specific owners, priority rankings, delivery percentages, deadlines, budgets, revenue, staffing capacity or confirmed milestones. Those remain **Not yet assessed** until the Founder / CEO confirms them or reliable project records are reviewed.

## 2. Portfolio Data Rules

The register must not invent or infer:

- Project owner or assigned Virtual AI role
- Project priority or business criticality
- Start date, deadline or release date
- Budget, revenue, costs or profitability
- Completion percentage or delivery status
- Customer commitments or contractual obligations

These fields remain **Not yet assessed** until supported by a Founder decision or project evidence.

## 3. Required Project Record

Each project should eventually have:

- Unique Project ID
- Official project name
- Product / service category
- Business objective and target users
- Scope and exclusions
- Founder-approved priority
- Human accountable owner (currently Founder / CEO unless changed)
- Proposed Virtual AI role assignments
- Current phase and verified status
- Milestones and acceptance criteria
- Risks, dependencies and decisions
- Budget / commercial assumptions, if approved
- Repository and technical environment references
- QA / UAT evidence
- Release approval and audit references

## 4. Project Lifecycle

**Idea → Discovery → Requirements → Planning → Architecture → Development → QA → UAT → Founder / CEO Release Approval → Release → Support / Improvement**

A project must not be marked released, live or commercially available without evidence.
